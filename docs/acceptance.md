## 阶段 2：视觉增强

**验收标准**

- [x] 所有视觉效果均为渲染层实现，engine 目录零改动
      —— `git diff --stat HEAD~1 -- src/engine` 输出为空；年龄与余晖状态住在 `src/render/visual-state.js`
- [x] 开满所有效果后 200×200 仍保持 60fps
      —— **前台浏览器实测 60fps 稳定（用户验收确认）**。
      辅助测量：每帧（引擎一代 + 视觉状态一代 + 渲染一帧）中位 **2.5ms** / p95 **3.2ms**，
      占 16.67ms 预算的约 15%；关掉全部效果为 1.9ms，拖尾图层的增量约 0.6ms。
      测量时每帧用 `getImageData` 读回一个像素强制刷完绘制管线，否则 Canvas2D 会把工作排队到 GPU、
      测出的 0.6ms 并不真实。

**功能项（浏览器内验证）**

- [x] 年龄着色：新生亮色 → 随存活代数渐变加深；3 个色带预设（翠绿 / 熔岩 / 冰川），亮度逐级单调递减
- [x] 死亡余晖：默认 4 代（可调 3–5）渐隐残影，亮度按 (d/n)^1.8 衰减，明显暗于活细胞
- [x] 拖尾模式：开关 + 长度滑块，走独立图层叠半透明层不完全清屏
- [x] 统计面板：代数 / 存活 / 出生 / 活动区 / 孤独死 / 拥挤死 实时显示
- [x] 存活数折线图（最近 500 代），带峰值参考线，主色跟随色带
- [x] 关闭全部效果时的画面与阶段 1 完全一致（同一条渲染路径）

## 阶段 3：条款规则编辑器

**验收标准**

- [x] 用条款编辑器手工搭出 B3/S23，规则指纹与预设 Life 完全一致
      —— 自动测试覆盖三种写法（`eq`/`range` 版、只写 2 条靠兜底补齐版、预设版），指纹均为 `9eba4f34`；
      界面里也实测：载入 HighLife → 点掉第 1 条条款的 chip「6」→ 指纹变为 `9eba4f34`；
      反方向（点 B/S 勾选框改条款）同样落到 `9eba4f34`
- [x] 切换到 Seeds 预设后运行，任意活细胞下一代必死（自动测试）
      —— 随机盘演化一代后上一代活细胞存活数为 0，并逐个邻居数查表确认 `lookup[活][n] = 死`
- [x] 构造一条永不可达条款，校验器能标出
      —— 三类分别测：被遮蔽 / 状态不可达 / 冗余；界面里新增条款被立刻标灰并给出原因，
      且删掉它指纹不变（证明它确实没有语义作用）

**功能项（浏览器内验证）**

- [x] 条款列表 UI：增 / 删 / ↑↓ / 拖动排序，当前状态、邻居条件、结果状态三个下拉
- [x] 邻居条件支持 `∈ / ∉ / = / 介于 / ≤ / ≥ / 任意`，集合用 0–8 chip 勾选
- [x] 衰老态（Generations 族）：层数 0–8，附「生成衰老链」一键补齐 衰老1→…→死亡
- [x] B/S 18 个勾选框与条款列表双向同步；超出表达力时置灰并**指名具体条款**
      （实测 Brian's Brain：「第 2 条条款会产生「衰老 1」，超出 B/S 记法只有生/死两态的表达力」）
- [x] 内置预设 5 个：Life / HighLife / Seeds / Brian's Brain / Day & Night
- [x] 条款校验器**与编辑器同期交付**：每次改动都重跑 结构校验 → 编译 → 语义校验，
      结构错误时禁用「应用规则」并逐条指出问题（越界的状态值在下拉里显示为「⚠ aging_1」，
      不会和错误提示自相矛盾）
- [x] 规则指纹实时显示在编辑器标题栏与主界面侧栏
- [x] 规则导出 / 导入：可表达时用 B/S 记法字符串，否则退化为条款 JSON；非法输入给可读错误
- [x] 编译表预览（状态 × 邻居数），靠隐含兜底决定的格子用虚线标出
- [x] 衰老态在画布上有独立配色（否则 Brian's Brain 的将死细胞会完全不可见）
