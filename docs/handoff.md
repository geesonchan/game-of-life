- **补丁自带前提**：`w/h/规则记号/世代戳`，对不上先说再丢。**戳打在闸那一处**，
  新增写盘路径自动被覆盖；`engine.step()` 不过闸，有自己的守卫（跑一代作废整栈）

- 核心文件：`src/data/undo.js`（纯）、`app.undo/restoreSession/refreshUndo`（main.js）

**两处与定稿不一样，都记在 D111**：
① 手机上四颗按钮实测 **82px 宽 × 44px 高**，不是定稿估的 88px；

**已知取舍**：整盘写过一次之后，它**之下**的补丁退不回去（撤掉清空可以，
再往下撤那一笔画不行）。这是"绝不按错坐标回滚"换来的，方向是对的，
但"多步"在跨越整盘改动时会缩水成一步。

## 六、冷启动七条（踩过坑才写下来的）

1. **推了才算交付。交付的定义是推上去了，不是本地绿了。**
   真机复验前先 `curl 线上页面 | grep app-version` 对版本号（D92）。
   **并且：要别人验之前，先确认线上有**（D112 ②）。
   这一条最老，还是踩了 —— 而且踩法是**新的**：
   前几次是"我验的不是线上产物"，v1.20.0 那次是"**我让别人去验一个不存在的产物**"。
   自己验错顶多浪费自己的时间；让作者去真机上找一颗还没推的按钮，浪费的是他的时间，
   而且他会先怀疑自己看漏了。**要求别人验，比自己验更该先对版本号。**
   最省事的做法：交付那一步就是"推 + 报线上版本号"，两件事绑在一起说，别拆开。
2. **验分支要照抄用户的复现步骤。** 他说"空盘直接点"，就不许先点随机填充（D105）。
   **"走真实交互路径"也算这一条。** v1.21.0 那次我报"播放中误触一笔实测可撤"，
   实际是直接调 `engine.set()` + `pushUndoSnapshot()` —— **验的是记账，不是交互**。
   结论碰巧对，但我给的证据支撑不了它。**要验交互，就得发真的指针事件。**
3. **立了判据，就问一句"它有守卫吗"**（D113 §5）。
   **一条教训只写成判据，等于没写完；配上守卫才算写完。**
   证据：「流内流外」刚升成通则，下一轮就在同一位置又漏一次；
   而 `#app` 那条规则旁边**就写着**为什么用 dvh，照样漏。
   判据要人想起来才有用，而证据是人不会想起来。
   （扫荡结果见 D113 §5：30 条判据里扫出 1 条没守卫的，恰是刚立下那条。）
4. **守卫写完必须红一次**，而且**匹配式必须唯一命中**（D110 §30）——
   **一条守卫同时管两份数据时，必须分别断言，不许拼起来查**（D131 §6）：
   `DICT.zh[k] + DICT.en[k]` 那种写法，一边通过就掩盖另一边 ——
   它从"两个都对"退化成"至少一个对"，而红的时候你看不出来。
   四次假守卫里三次是"匹到了别的东西"。定位一律走 `locate()`，命中数不对就红。
   注释里对代码位置计数的话（"只有一处"/"唯一出口"）算**说的与做的**那一族的第五面，
   要在 `src/data/structure-claims.js` 登记（D110 §12）。
5. **验收打勾要在 commit 之前单独确认。**
   顺带：**报数时正例和反例都要检，不能只检正例的格式**（D11 后补）。
   v1.23.0 这一轮我给 cases.js 加了一条重复的 `import { Ledger }` ——
   **Vitest 照样绿，JSC 直接抛 `Cannot declare an imported binding name twice`**。
   而我只 `grep "通过 /"`：异常那一路根本没有"通过"那一行，**没找到就被我当成了没输出**，
   于是它红了两轮我都没看见。
   工具在正常与异常两种情况下输出的形状不一样；只对着正常那一种找，**异常就是静默的**。
   这与我们追了一路的那一族同形：**没有输出，被当成了没有问题。**
6. **验按时间触发的东西，要用它在生产里真正收到的那个时钟**（D110 §26，差的是量纲）。
7. **时序冷启动：在"还没就绪"的那一刻验**（D110 §5）。
8. **数要量，不要猜**（D82）。
   顺带：**结构守卫全绿不等于跑得起来**。D123 那次加 `touchDraw`，
   守卫全绿而应用在浏览器里直接起不来（D30 的 `PREF_KEYS` 白名单在运行时抛）——
   运行时的约束，结构扫描看不见。**只跑测试不算验过。**
9. **底部安全区这一类，只能真机验**（D112）。iPhone 的 home indicator（上滑退出横条）
   是**系统 UI**，模拟视口里**根本不存在** —— 任何压在它上面的可点区域都会被系统抢走手势，
   而结构上看不出来：位置、尺寸、层级全是对的。

   **验法**（三步，前两步在模拟视口里就能做，第三步只能真机）：

   1. **注入横条再逐点探**，别靠眼睛。把 `--safe-b` 手工设成 34px，
      然后沿屏幕底沿由下往上 `document.elementFromPoint(x, 视口高 - n)`，
      n 取 5 / 20 / 33 / 40 / 60，看**每一点上接点击的到底是谁**。
      判据写成可复验的断言：**"横条那一带里探到的只有把手自己"** ——
      而不是"看起来没压着"。第一版就是这么抓出来的：抽屉抬高之后，
      那一带里探到的是可点的分组标题，**危险目标只是被换掉了，没有消失**。
   1b. **逐点探只能探到探测那一刻存在的东西 —— 有几种界面状态，就得探几遍**（作者定）。
      v1.20.1 那次探完说"只有抽屉把手在危险带里"，是**在引导关着的时候**探的；
      引导是另一层（`position: fixed`），当时根本不在 DOM 的可见层里，探不到。
      **会盖住底部的状态清单**（每加一个新浮层就往这儿加一行）：

      | 状态 | 谁负责让开 |
      | --- | --- |
      | 引导三幕 / 挡路框 / 总结卡片 / 规则编辑 | 四个共用 `.modal` 一处 |
      | 观塔 / 勘探 / 临界（全屏视图） | 三个共用 `.tower-view` 一处 |
      | 设置抽屉（收起：只露把手；展开：整面板） | `.panel`（锚点 `top: 100dvh`）+ `.drawer-handle` |
      | 临时撤销条 / 小地图 / 重放条 / 「放这」按钮 | 都在 `#app` 的流里，`#app` 一处让开 |
      | 「更多」浮层 | 挂在顶上且封了高度，**够不着底**（守卫会盯着它别变成触底浮层） |

      **`#app` 那句 `padding-bottom` 罩不住 `position: fixed` 的浮层** ——
      它们不在 `#app` 的流里，各自得让开。所以有一条**结构性守卫**：
      凡是 `position: fixed` 且够得着底边（`inset: 0` 或写了 `bottom:`）的规则，
      必须引用 `var(--safe-b)`，否则当场红 —— 新加浮层忘了让开，不必靠记性。
   2. **代码侧钉 `viewport-fit=cover`**：少了它 `env()` 恒为 0，整条修法**悄悄空转**。
   3. **真机**（不是模拟视口）：底部每个可点区域各点五次，看要不要"额外小心"。

   **底部的系统 UI 有两样，别只想着一样**（D115，作者点名）：

   | | 是什么 | 多高 | 模拟视口里 |
   | --- | --- | --- | --- |
   | home indicator | 上滑退出的横条 | ~34px | **没有** |
   | **浏览器工具栏** | Safari 底部的前进/后退/分享/标签页 | **比横条高得多**（~50px 起，还会随滚动收放） | **没有** |

   **贴底的固定定位元素必须同时管住这两样**（D117，守卫钉住）——
   已经在同一个位置漏了三次（横条一次、工具栏两次）。
   查的是**锚点**不是"提没提过 dvh"：抽屉那一版写着 `max-height: 76dvh`，
   提过 dvh，锚点却还是 `bottom: 0`。

   两样**各让各的**，机制也不同：
   · 横条 → `env(safe-area-inset-bottom)`（要 `viewport-fit=cover`）；
   · 工具栏 → **视口单位**：`vh` 和 `position:fixed; inset:0` 量的都是
     "工具栏收起时"的最大高度，**要用 `dvh`**。
   而且它俩**此消彼长**：工具栏露出来时它盖住横条，工具栏收起时横条露出来 —— 所以都要让。

   **上一轮我只让开了横条（34px），没让开工具栏** —— 于是引导第二幕的按钮
   在模拟视口里量出来"清出危险带了"，真机上照旧贴着底栏。
   **模拟视口里两样都不存在**，所以这一格只能真机截图验。

**"验的不是同一情形"这一族已经十一个成员**：
不是同一版（D92）/ 不是同一条路（D105）/ 不是同一种人（D107）/ 不是同一个时刻（D110 §5）/
不是同一个会话阶段（§10）/ 不是同一个量纲（§26）/ **不是同一个工作环境**（v1.19.2 那次
在降级沙箱里推的线上，作者点名要记）/ **不是同一个设备的系统 UI**（D112：模拟视口里
没有 home indicator，压在它上面的可点区域只有真机才暴露得出来）。

第八个成员与前七个有一点不同，值得单说：前七个是"我验了，但验的是别的情形"，
**第八个是"我验的那个环境里，那件东西根本不存在"** —— 不是量错了，是无从量。
这一类只能靠真机，加上把前提（`viewport-fit=cover`）钉死在守卫里。

**第九个：不是同一个方向**（D114）。撤销的"两个入口一个 token"是**双向**的性质，
我只验了"点条子 → 按钮也熄"，没验"点按钮 → 条子也熄" —— 后者正是坏的那一向。
**一条双向的性质，验一向不算验过；而且验过的那一向会让人以为整条都验过了**，
这正是它比"完全没验"更危险的地方。
**验法**：性质里出现"两处 / 双方 / 互相 / 同时"这类词，就**逐向各钉一次守卫**。

**第十个：不是同一个浏览器**（D117）。同一台真机，Safari 与 Chrome 的**底部工具栏几何不同** ——
抽屉偏低那次就是作者在 **Chrome iOS** 上撞到的，Safari 上没看出来。
**验法**：底部那一类改动，两家各验一遍。

**第十一个：不是同一种指针**（D128）。模拟器里用**鼠标**点，不会重现**手指**的行为 ——
手指落点带弧线，一划就超过浏览器合成 `click` 的容差，那一下**静默丢掉**。
"点几次才有反应"这一类**只能真机验**；模拟器里能验的只有容差、尺寸、遮挡。
