## 五、冷启动六条（踩过坑才写下来的）

1. **推了才算交付。** 真机复验前先 `curl 线上页面 | grep app-version` 对版本号 ——
   本地绿、线上是旧版，查一整轮也查不出（D92）。
2. **验分支要照抄用户的复现步骤。** 他说"空盘直接点"，就不许先点随机填充再点 ——
   那是另一条分支（D105）。同理："不是同一版 / 不是同一条路 / 不是同一种人 / 不是同一个时刻"，
   四次都栽在"我验的和他走的不是同一个东西"上（D110 §5 是第四次）。
3. **守卫写完必须红一次。** 每条新守卫都要注入一个破坏、看它变红，再复绿。
   自查里抓到过一大批"看着在管、其实管不着"的假守卫（子串匹配、匹配到别处的同名行、
   该扫原文却扫了 `stripLiterals` 的输出 —— 后者犯过四次，见 D88 §3）。
4. **验收打勾要在 commit 之前单独确认。** 补丁没匹配上也会照常提交，出过两次。
5. **时序冷启动：在"还没就绪"的那一刻验，不是在稳定之后。**
   前四条差的是**环境**（版本、路径、人），这一条差的是**时间**，是另一类。
   布局没跑、资源没到、面板隐藏、首帧之前 —— 那一刻的画布是 300×150 的出厂值，
   不是它稳定后的样子。D110 §5 那个 bug 就藏在这里：稳定之后验一百遍都是绿的。
   验法：故意在就绪之前调用（把 `renderer.resize` 打桩成返回 0、或在 rAF 之前直接调函数），
   看那条路自己撑不撑得住。
6. **数要量，不要猜**（D82）：每个数字都得答得出"被什么裁出来的"。
   帧率、耗时、像素偏移、字符长度，一律实测后写进文档。

## 六、跑起来

```bash
npm install && npm run dev      # 本地开发（别用 Bash 起服务，用预览工具）
npm test                        # vitest
npm run test:jsc                # JavaScriptCore 运行器，同一份 tests/cases.js
npm run build                   # 构建会把 package.json 的版本号盖进 <meta name="app-version">
```

浏览器里 `window.__lab` 就是整个 app —— 核对启动路径、取景、指纹都靠它。
面板隐藏时 rAF 不跑，`handleResize()` 要手动调一次，否则画布停在 300×150 的出厂值
（D110 §5 那个 bug 就是这么现形的）。
