# 生命游戏实验台 · v1 复盘

> 收官时的规模：18 次提交、8,436 行源码与测试、76 条自动测试、59 条设计决策、6 轮用户反馈。
> 六个规格阶段外加四个插入阶段（3.5 双语与简洁模式 / 3.6 文案与引导 / 3.7 布局重构 / 5.5 时间之塔）。

---

## ① 流程资产

整个项目跑的是同一个闭环，跑了十轮：

```
规格前置 → 分阶段 → 每阶段先立验收标准 → 实现并自测 → 真人验收 → 反馈落档 → 下一阶段
```

### 规格前置

动手之前先有一份完整的规格书（`game-of-life-spec.md`），里面有架构约束（三层分离、规则预编译、
确定性、双缓冲、数据与渲染节拍解耦）、数据结构约定、分阶段计划和每阶段的验收标准。

**它的价值不在于"照着做"，而在于它会和现实顶牛，逼出真正的决策。** 本项目至少顶了四次：

- `then` 只能取 `aging_1`，却又允许 0–8 层衰老 —— 三条同时成立时第 2 层以上必然不可达（D17）
- 「区域灭绝」要求连通块识别，而规格自己把结构级追踪划给了 v2（D36）
- 「不使用 localStorage」与「介绍卡只在首次弹出」不可兼得（D29 → 用户修订规格 → D30）
- 验收标准提到「长周期」，而结局分类只点名了五类（D57）

每一次顶牛都比闷头实现更有价值：它把一个隐藏的取舍摆到台面上，要么由我给出理由并记录，
要么上交给用户裁决（localStorage 那次就是用户直接修订了规格）。

### 分阶段 + 验收标准前置

阶段的粒度是"能独立验收的一段"。**每个阶段的验收标准写在动手之前**，而且尽量写成可执行的判据
（"blinker 第 2 代检测到 cycle 且周期报 2"，而不是"循环检测应该正确"）。

这带来一个反直觉的好处：**验收标准会倒逼实现的形状**。
- 「手搭 B3/S23 与预设 Life 指纹一致」逼出了"判定必须站在编译产物上而不是源码文本"（D18）
- 「滑翔机斜线 / blinker 麻花柱 / 静物直柱」逼出了"几何断言建在数据层，不依赖渲染器"（D50）
- 「循环检测在一万代规模无卡顿」逼出了复杂度守卫测试

### 真人验收

我自测通过不等于验收通过。用户在真实浏览器里跑，负责我够不到的部分：

- 我测不到的东西（前台 60fps、真机 Shift 手势、观塔环绕帧率）
- 我测得到但测错了的东西（读档后满屏新生白、随机初始化"没反应"）
- 我根本想不到的东西（布局的信息架构、框选的流程顺序、"切去烟花世界忘了切回来"）

**六轮反馈里有四轮是我自测全绿之后提出来的。** 这条渠道不可替代。

### 三份文档的分工

| 文档 | 回答什么 | 谁写、何时写 | 特点 |
| --- | --- | --- | --- |
| `acceptance.md` | **做到了没有** | 每阶段收尾，commit 前单独确认 | 逐条打勾，每条附上"怎么验的、实测多少"；未做到就明确留空并说明 |
| `decisions.md` | **为什么这么做** | 决策发生的当时 | 一条一段，重点写**否决了什么、为什么否决**；写错了就标注被取代（D29→D30）而不是删掉 |
| `feedback.md` | **谁说的、怎么理解的** | 每轮用户反馈 | 原话诉求 → 我怎么理解 → 做了什么；论证展开在 decisions，这里只留链路 |

三份分开的理由：它们的**读者和生命周期不同**。验收清单是给"现在能不能封版"看的，
决策记录是给"三个月后想改这里的人"看的，反馈记录是给"想知道这个设计从哪来"的人看的。
混在一起会让每一份都变钝。

### 流程本身也出过错

阶段 3 和阶段 4 各有一次：我用 `python 改文件 && git commit` 的串联写法，
补丁的 `assert` 失败了但 commit 照常执行，提交里少了打勾，只能事后 amend。
用户把它定为流程规矩：**打勾必须在 commit 前单独 `git diff` 确认**，不把两者串在一条命令里。
amend 补救不算数 —— 提交历史里那一版本身是错的。

## ② 方法清单

可迁移的做法，每条一句话，附本项目里的出处。

**测试**

- **测试先行且变异验证** —— 写完守卫就把 bug 装回去看它是否变红；没红过的测试不算数（接线守卫三条、种子框预填、`<label>` 包按钮，都做过变异验证）。
- **绿灯陷阱** —— 测试通过可能是"恰好蒙对"：blinker 只出现两次，掩盖了"周期算成距首次多久"；随机盘第 0 行几乎必有细胞，掩盖了 `toRLE` 漏写开头空行。**要为你的判据专门找一个能证伪它的例子**。
- **复杂度守卫** —— 与其断言"用了 Map"，不如断言"条数 ×5 时耗时只 ×3.4，而线性扫描应接近 ×25"；断言行为，不断言实现。
- **接线守卫** —— 静态扫源码与 HTML：`getElementById` 的 id 必须真实存在、`<label>` 里不许有 `<button>`、种子框开机必须为空；守的是"重构后绑定悄悄落空"这一整类事故。
- **等价性测试要配反例** —— 「年龄只补跑最后 80 代与从头跑满渲染结果逐格相同」这条断言，必须同时证明"预热只有 8 代时确实会露馅"，否则这个等价性可能是空的。
- **词典完整性靠测试** —— 键集一致、占位符逐条对应、简洁语域禁用词表；漏翻和占位符错位都不会报错，只会难看。
- **把决策逻辑抽成纯函数** —— 异步 rAF 分片、鼠标事件里的定位夹取都极难测，摘成 `shouldShowProgress()` / `placeSelectionMenu()` 就是普通函数。

**测量**

- **测量要强制刷新管线** —— Canvas2D 把工作排队给 GPU 就返回：第一次测出 0.6ms/帧是假的，每帧 `getImageData` 读回一个像素才得到真实的 2.5ms。
- **测不了就说测不了** —— 预览面板 rAF 被节流、`gl.finish()` 不生效、自动化工具的 `modifiers` 传不到页面：这些都如实写进验收清单并交给用户真机确认，而不是拿一个假数字打勾。
- **标定先于编码** —— 「爆炸」的判据、勘探的棋盘尺寸与起始密度，都是先跑实验看数据再写死阈值；第一版凭感觉定的绝对占比阈值让**所有规则都判成了爆炸**。

**调试**

- **状态对 ≠ 画面对** —— 观塔与勘探两个整屏视图叠在一起时 `isOpen` 全是对的；塔全黑时 `getColorAt` 读回来是正确的绿色。只看状态量查不出来，必须看画面。
- **先验数据再疑管线** —— 塔全黑时先确认颜色数据正确，才去查着色器，于是找到 `vertexColors` 打开了 `USE_COLOR` 而几何体没有 `color` 属性；反过来先调亮度会调很久。
- **复现不了就换一层验证** —— 工具传不了 Shift，就用带 `shiftKey` 的真实 `PointerEvent` 覆盖那一支，同时用另一个入口做全真实点击，并说明哪一半是替代验证。
- **警惕验证环境本身** —— Vite 下从控制台 `import()` 拿到的是**另一个模块实例**，`lang`/`register` 与应用不共享；我因此一度误判英文语域坏了。验证界面行为要走真实 UI。

**架构**

- **判定站在编译产物上，不站在源码文本上** —— B/S 表达力用查找表的可达闭包判定，因为指纹也是查找表的哈希；否则会出现"两条规则指纹相同，一个能勾一个被置灰"。
- **纯逻辑层不持有人类语言的句子** —— 校验器只返回 `{key, params}`，句子由界面层拼；好处不止于翻译，测试也从"断言中文子串"变成"断言 key"。
- **Worker 只搬运，逻辑留在可测的地方** —— 时间之塔与规则勘探的 Worker 都只有二十行，`buildTower()` / `exploreRule()` 是普通函数。
- **几何断言建在数据层** —— "斜线/麻花柱/直柱"听起来是视觉判断，本质是对 `(x, y, 代数)` 的断言，不需要渲染器；画错了是渲染的问题，形状不对是数据的问题，分开查。
- **声明式优于命令式** —— 简洁/完整模式用 `data-mode` 标注 + 两条 CSS 规则，加新控件时只需回答"它属于哪个模式"，不用维护越来越长的 `toggleVisibility()`。

**产品**

- **退化必须可见** —— 快照抽稀、塔的实例抽稀、滑动窗口丢层，都在界面上如实写出条数与倍率；精度可以退化，退化不能悄悄发生。
- **顺序对了，提示就不必要** —— 框选原本是"先点按钮宣布模式 → 再回棋盘拖框"，提示条只是在错误的顺序上贴说明；改成"Shift 拖直接框，松手才问要干嘛"之后，提示成了锦上添花。
- **默认值就是语义** —— 种子框开机预填一个值，等于把"留空则随机生成"的语义反过来了，用户看到的是"按钮没反应"。
- **两种语域不是两份词典** —— 简洁模式与完整模式共用一套 key，只有真正需要改口的几十条写 `.simple` 变体；"跟同学解释，不是哄小朋友"这条标准靠禁用词表落成可执行判据。
- **控件在最需要它的那一刻必须够得着** —— 介绍卡首屏盖住了侧栏的语言开关，而看不懂第一屏正是最需要换语言的时刻，所以卡片自己也要有一个。

## 收尾

v1 的六个规格阶段全部通过验收，`acceptance.md` 零未勾项。

如果只留一条给下一个项目：**先把"怎么算做到了"写清楚，再动手**。
本项目里最有价值的几个设计决策——可达闭包判定 B/S 表达力、几何断言建在数据层、
校验器只返回 key——没有一个是想出来的，全是被验收标准逼出来的。
